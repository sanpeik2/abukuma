異常 → 作業 → 安全ゲート 導線ガイド

点検で異常を見つけてから、作業票・作業許可（KY/PTW/LOTO）・作業完了・報告までの「流れ」と「ボタン」の対応表です。各ボタンは実装済みです。
● 実装済み（押せる） ● 条件付き（ゲート充足時のみ押せる） 画面：file.html
1点検実施inspection-input.html
点検結果を「異常あり」で記録すると、状態が自動で「🚨 異常判断中」になります。
ボタン遷移先状態
🔧 異常判断へdefect-rca.html?inspection_result_id=…&plan_id=…
（NG項目を引き継ぎ）		✅
📨 承認申請 ※異常なし時点検結果の承認（approvals.html）✅
▼
2異常判断（一次評価・RCA）defect-rca.html
異常の安全影響・原因・判定を評価し、承認申請・作業票起票・法令分類を行います。
ボタン遷移先 / 動作状態
📨 承認申請submitDefectApproval() → 承認画面で承認✅
📝 作業票を作成work-orders.html?defect_finding_id=…&inspection_result_id=…
（号機・異常内容・判定・NG項目を引き継ぎ）		✅
点検結果を見る →inspection-input.html?…&readonly=1✅
⚖ 法令・報告分類（A〜F）report-candidates.html（報告候補で確認）✅
▼
3承認（異常報告）approvals.html
主任が異常報告（defect_finding）を承認します。承認は承認画面に集約。
ボタン動作状態
✅ 承認defect_findings.status=assessed / approval_status=approved（証跡は approvals）✅
↩ 差戻しapproval_status=returned✅
▼
4作業票（要否の設定・進行管理）work-orders.html
作業票は KY/PTW/LOTO の要否を持ち、安全実施状況をサマリ表示します。実施・証跡は作業許可側です。
ボタン遷移先 / 動作状態
✏ 編集安全要件 KY要 / PTW要 / LOTO要 を設定（要否）✅
📨 承認申請作業票の承認（approvals.html）✅
⚠ 作業許可・KY/LOTOを開くky-loto.html?work_order_id=…✅
▶ 作業開始status=in_progress
安全ゲート充足時のみ有効		条件付
✅ 作業完了・クローズstatus=completed
LOTO解除まで完了時のみ有効		条件付
🔒 安全ゲート（v_work_order_safety_status で判定）
・作業開始可＝ KY実施済 ＋ PTW=approved（closedは不可）＋ LOTO施錠済
・クローズ可＝ KY実施済 ＋ PTW=approvedまたはclosed ＋ LOTO施錠 かつ 解除済
・未完了は赤帯で表示：KY未実施 / PTW未承認 / LOTO未施錠 / LOTO未解除
▼
5作業許可・KY・LOTO（実施・承認・解除の正本）ky-loto.html
作業票の要否を読み込み、必要な安全ゲートと「次にやること」を提示します。証跡はここに記録。
操作動作 / 記録先状態
KY記録を作成・確定ky_records（confirmed_at）✅
PTW 申請 → 承認work_permits（permit_status=approved）／permits.html・approvals.html✅
LOTO 施錠 → 解除loto_records（status=locked → unlocked）✅
▼
6クローズ・報告候補report-candidates.html
作業完了（LOTO解除済）でクローズ。保安規定の報告候補は電気主任技術者が最終判断。
確認動作状態
⚖ 報告候補を確認v_report_candidates（法令分類A〜F・報告候補フラグ）✅
要否は作業票、実施・承認・解除の証跡は作業許可/KY・LOTO。同じ実施チェックを二重管理しません。
安全ゲート判定ビュー：v_work_order_safety_status（ky/ptw/loto の要否・状態・safety_ready_to_start・safety_ready_to_close・blocking_reasons）。
