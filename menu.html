② O&M業務プロセス— 全体像と判断順序を確認DOC

⚙ 業務フロー全体図（11ステップ）DOC
今日の管制塔 → 監視 → 点検計画 → 点検実施 → 異常判断 → 作業票 → PTW/KY・LOTO → 承認 → 作業実施 → 復旧確認 → クローズの全体像。PTW・KY・LOTOの使い分けと法令根拠付き。
🔀 異常→作業→安全ゲート 導線ガイドDOC
「異常が出たら次に何を開くか」迷ったときの導線マップ。異常判断→作業票→PTW/KY・LOTOの接続ロジック

③ 点検— 計画して実施・記録する

📅 点検計画一覧LIVE
年次/定期/随時の点検計画。期限超過・本日をハイライト、区分・状態で絞り込み（v_inspection_plan_list）
🛠 点検実績入力LIVE
点検結果・異常・BOXリンクを登録し、最近の実績を一覧表示（inspection_results / v_inspection_results_list）
① 点検計画の基本DOC
いつ・何を・誰が点検するか。年次/定期/随時の3区分と期限管理
② 点検実行の基本DOC
現地で見る・記録する。見るポイントと「異常なしも記録」の考え方
📋 点検ルールマスタLIVE
点検区分・頻度・対象機器・実施基準の一覧。点検計画を作るときの基準表

④ 異常・故障対応— アラーム/故障が出たとき

🔧 故障 / 根本原因調査(RCA)LIVE
異常の評価・RCA対象の抽出・是正の進捗。行クリックで根本原因/暫定・恒久処置を展開（v_defect_rca_list）
🧭 考え方フロー図DOC
異常発見→一次評価→A〜F判定→是正→クローズの判断ロジック
🔧 異常是正フローDOC
defect_findings から closeout までのデータの流れ
③ 異常評価・是正判断の基本DOC
直すか・様子見か・報告か。安全/発電/法令の3軸で判断
⑦ 故障対応・RCAの基本DOC
止血（暫定）で終わらせず真因を断つ。RCA対象の見分け方と恒久処置の考え方（並行）

⑤ 作業・安全・承認— 起票→PTW/KY・LOTO→承認→実施→復旧

📝 作業票を起票・確認LIVE
異常・点検計画から作業票へ進む工程入口。停止影響、発電損失、作業状態をここで確認する
⚖ 主任確認が必要な候補LIVE
作業・安全工程で主任確認が必要な異常を逃さないための警告入口。最終判断は法令・報告工程で確認
🔒 作業許可 (PTW) 一覧LIVE
高所・電気・LOTO・火気などの許可管理。状態・リスク・安全要件で絞り込み（v_permits_full）
⚡🔒 KY・LOTOシートLIVE
現場作業前の危険予知（KY）チェックシートとロックアウト/タグアウト（LOTO）記録。点検計画・作業票の各行リンクから遷移。⚖ 労働安全衛生法対応
✅ 作業前ゲートの承認LIVE
作業実施前に止めるべき承認を確認。主任技術者・担当者の承認待ちを工程内で解消する
④ 作業票の基本DOC
直す作業を指示書にする。起票の契機と恒久処置まで追う考え方
⑤ 作業許可(PTW/LOTO)の基本DOC
安全に止めてから作業する。LOTO（止める→施錠→確認）の考え方
⑥ 主任承認の基本DOC
何を確認して承認するか。証跡と差戻し理由の考え方
🔨 作業実施LIVE
承認後の作業実施記録。実施内容・作業者・完了時刻を登録（work_execution）
🔄 復旧確認LIVE
作業完了後の設備復旧・試運転確認。LOTO解除・起動確認を記録
✔ クローズ・報告確認LIVE
案件のクローズ処理と報告要否の最終確認。保安規定報告・是正完了の証跡を締める

⑥ 法令・報告— 保安規定・事故報告

⚠ 安全・異常報告LIVENEW
ヒヤリハット・事故・設備異常・環境事象・作業逸脱・改善提案を独立管理（v_safety_incidents）。60秒クイック報告。作業票がなくても登録可
🔀 ヒヤリハット vs 異常報告 の使い分けDOC
何をどこに記録するか・どちらが先か。safety-incidents と defect-rca の違いと接続フロー
⚖ 保安規定・事故報告判断LIVE
候補理由を確認し、主任技術者が報告要否を判断する入口（v_report_candidates）。RCA・作業票への深掘り導線あり
📋 事故報告フローDOC
保安規定にもとづく事故報告の流れ（覚知→速報→詳報→記録）＋🚨緊急時チェックリスト
⚖ 報告候補リストの使い方DOC
区分A〜Fの意味・候補理由バッジの読み方・次のアクション・作業票を起票するタイミング

⑦ 横断管理— 全案件の進捗と滞留を俯瞰管制塔

🗺 ワークフロー管制LIVE管制塔
異常・故障対応の全案件の現在地・滞留・次アクションを横断確認。駅マップ＋案件タイムライン＋期限超過/報告候補/主任確認フラグ。点検予定・安全ヒヤリ・報告候補への入口も件数バッジ付きで集約（v_case_pipeline）
